The Stripe interface has functions that watch payment intents. A watcher callback runs each time the implementing module reports an event for a payment intent, so your application can react to successful payments, cancellations, and other status updates.

Use [`WatchPayment`](#watchpayment) for one intent and [`WatchAllPayments`](#watchallpayments) for observers of every payment. Callbacks run in memory, not in a durable job queue. The `sendConfirmationEmail` and `updateOrderStatus` calls below stand for your own code. Supply idempotent handlers, and handle their errors.

## Observe a payment

Register a watcher for an intent ID that your checkout code saved. The watcher logs the future events that the configured implementation reports. It does not retrieve the current Stripe status, and it does not replay events that arrived before the registration.

```typescript
import { WatchPayment } from "@antelopejs/interface-stripe";

WatchPayment("pi_replace_with_your_test_intent", (orderId, intent) => {
  console.log({ orderId, paymentIntentId: intent.id, status: intent.status });
});
```

To retrieve the current status before you wait for a terminal event, use [`WaitForPayment`](./2.payment-processing.md#waitforpayment). Persist the intent ID, so your application can reconcile after a restart.

Keep callbacks short, and handle errors inside them. The interface calls them synchronously and does not await the promises that they return. A synchronous throw skips the callbacks that come after it and the cleanup of a terminal state, for that event. Asynchronous work needs its own rejection handling and recovery policy.

## `IntentChangeContext`

The context object that every watcher callback receives. It tells where the event came from.

```typescript
interface IntentChangeContext {
  local: boolean;
}
```

| Property | Type      | Description                                                                                                        |
| -------- | --------- | ------------------------------------------------------------------------------------------------------------------ |
| `local`  | `boolean` | `true` when this instance received the webhook from Stripe. `false` when another instance relayed the event to it. |

The flag matters in a cluster, where the instance that receives a webhook relays the event to the other instances. A filter on `context.local` skips those relayed events. It does not remove repeated webhook deliveries from Stripe. Make side effects such as emails or database updates idempotent.

## `IntentWatcher` callback type

Every watcher function takes a callback with this signature:

```typescript
import type { IntentChangeContext } from "@antelopejs/interface-stripe";
import type Stripe from "stripe";

type IntentWatcher = (
  id: string | undefined,
  intent: Stripe.PaymentIntent,
  context: IntentChangeContext,
) => void;
```

| Parameter | Type                   | Description                                                          |
| --------- | ---------------------- | -------------------------------------------------------------------- |
| `id`      | `string \| undefined`  | Your identifier from `metadata.payload`, set by `InitializePayment`. |
| `intent`  | `Stripe.PaymentIntent` | The full payment intent object, in its current state.                |
| `context` | `IntentChangeContext`  | Where the event came from.                                           |

## `WatchAllPayments`

Registers a callback that runs on every payment intent event. Use it for side effects that cover all payments, such as logs, analytics, or audit trails.

```typescript
import { WatchAllPayments } from "@antelopejs/interface-stripe";

WatchAllPayments((id, intent, context) => {
  console.log(`Payment ${id} changed to status: ${intent.status}`);
  console.log(`Origin: ${context.local ? "local" : "remote"}`);

  if (intent.status === "succeeded") {
    // Handle successful payment
  } else if (intent.status === "canceled") {
    // Handle canceled payment
  }
});
```

### Parameters

| Parameter   | Type            | Required | Description                                                                                            |
| ----------- | --------------- | -------- | ------------------------------------------------------------------------------------------------------ |
| `callback`  | `IntentWatcher` | Yes      | The function that runs on every payment intent event.                                                  |
| `onlyLocal` | `boolean`       | No       | When `true`, the callback runs only for the webhooks that this instance received. Defaults to `false`. |

### Filtering local events

In a cluster, set `onlyLocal` to `true` to skip the events that other instances relay. The filter does not guarantee delivery exactly once.

```typescript
import { WatchAllPayments } from "@antelopejs/interface-stripe";

declare function sendConfirmationEmail(id: string | undefined): void;

// Only react to events from the current instance
WatchAllPayments((id, intent, context) => {
  if (intent.status === "succeeded") {
    sendConfirmationEmail(id);
  }
}, true);
```

`sendConfirmationEmail` stands for your own function. Its `declare` line only gives it a type.

The interface applies the `onlyLocal` filter before it calls the callback. When `onlyLocal` is `true`, relayed events never reach the callback.

## `WatchPayment`

Registers a callback for one payment intent. The callback runs on every event for that payment intent. When the intent reaches a terminal state (`succeeded` or `canceled`), the interface removes the watcher.

```typescript
import { WatchPayment } from "@antelopejs/interface-stripe";

declare function updateOrderStatus(
  id: string | undefined,
  status: "paid" | "canceled",
): void;

WatchPayment("pi_1234567890", (id, intent, context) => {
  if (intent.status === "succeeded") {
    console.log(`Payment ${id} completed successfully`);
    updateOrderStatus(id, "paid");
  } else if (intent.status === "canceled") {
    console.log(`Payment ${id} was canceled: ${intent.cancellation_reason}`);
    updateOrderStatus(id, "canceled");
  } else {
    console.log(`Payment ${id} status: ${intent.status}`);
  }
});
```

`updateOrderStatus` stands for your own function. Its `declare` line only gives it a type.

### Parameters

| Parameter         | Type            | Required | Description                                           |
| ----------------- | --------------- | -------- | ----------------------------------------------------- |
| `paymentIntentId` | `string`        | Yes      | The ID of the Stripe payment intent to watch.         |
| `callback`        | `IntentWatcher` | Yes      | The function that runs on every event for the intent. |

`WatchPayment` has no `onlyLocal` filter. Its callback runs for local events and for relayed events.

## Automatic cleanup

When a payment intent reaches a terminal state (`succeeded` or `canceled`), the interface cleans up:

- It removes the watchers that `WatchPayment` registered for the intent.
- It resolves or rejects the pending promise of `WaitForPayment` for the intent.

The cleanup covers only the registrations for that intent, after the interface processes the terminal event. Watchers from `WatchAllPayments` stay registered. Neither watcher function returns a handle that removes the watcher. Register the global observers once, when the application starts, and not once per request.

## Combine watchers with payment processing

The next example creates a payment intent, watches for its completion, and returns the client secret for the confirmation in the browser.

```typescript
import { InitializePayment, WatchPayment } from "@antelopejs/interface-stripe";

async function processAndMonitorPayment(orderId: string, amount: number) {
  const intent = await InitializePayment(orderId, {
    amount,
    currency: "usd",
    payment_method_types: ["card"],
  });

  // Register without waiting, then let the browser confirm the payment.
  WatchPayment(intent.id, (id, updatedIntent, context) => {
    if (updatedIntent.status === "succeeded") {
      console.log(`Order ${id} has been paid`);
    } else if (updatedIntent.status === "canceled") {
      console.log(`Payment for order ${id} was canceled`);
    }
  });

  return {
    clientSecret: intent.client_secret,
    paymentIntentId: intent.id,
  };
}
```

Watchers live in memory. Persist the intent ID, and reconcile unfinished orders after a restart, as the [separate reconciliation example](./2.payment-processing.md#complete-payment-flow) shows.

You can use `WatchPayment` and `WaitForPayment` on the same payment intent. Do not wait for completion before you return the client secret. The interface cleans up both when the intent reaches a terminal state.
