The Stripe interface has functions that create payment intents, wait for them to finish, and charge chargeable Sources.

## Pick the confirmation path

For a browser card checkout, start with the [complete payment flow](#complete-payment-flow). The server creates an intent and returns its client secret, and Stripe.js confirms the payment in the browser. The server reconciles the result in a separate step.

`CompletePayment` is a different operation, based on Stripe Sources. It creates a charge and updates the intent metadata. It does **not** call `paymentIntents.confirm`, so it has no place in the browser confirmation path.

## Complete payment flow

Return the client secret from the checkout request first. The browser needs it to confirm the payment with [Stripe.js](https://stripe.com/docs/js), so a wait for completion inside that request blocks the confirmation. Calculate the amount on the server from the saved order, never from a total that the browser sends.

```ts docs-check
import {
  InitializePayment,
  WaitForPayment,
} from "@antelopejs/interface-stripe";

export async function startCheckout(orderId: string, amountInCents: number) {
  const intent = await InitializePayment(orderId, {
    amount: amountInCents,
    currency: "usd",
    payment_method_types: ["card"],
  });

  return {
    clientSecret: intent.client_secret,
    paymentIntentId: intent.id,
  };
}

// Run separately from the request that returns the client secret.
export async function reconcilePayment(paymentIntentId: string) {
  const completed = await WaitForPayment(paymentIntentId);
  return { orderId: completed.metadata.payload, paymentIntentId: completed.id };
}
```

### Keep checkout and fulfilment separate

1. Persist the link between the order and the intent on the server.
2. Return the secret only to the authenticated payer.
3. Run reconciliation from a job that the server owns, with the saved intent ID. As an alternative, use [payment watchers](./3.event-monitoring.md) with the verified webhook events of the implementation.
4. Check the expected amount and currency of the order, then apply an idempotent fulfilment update.

`WaitForPayment` resolves only for `succeeded` and rejects only for `canceled`. It has no timeout, and it does not reject a payment that still needs action from the payer. Configure webhook delivery, handle cancellations and provider errors in the job, and give the job its own retry and recovery policy. A return of the browser to your site does not prove that the payment succeeded.

The functions above show the interface calls. They are not a complete HTTP route or a durable job. Before you retry the creation of a checkout, reuse the saved intent, or pass a stable Stripe `idempotencyKey` for that creation attempt in the third argument of `InitializePayment`. The order ID in `metadata.payload` is not an idempotency key.

## `GetClient`

Returns the Stripe client. The promise resolves when the implementing module starts and hands its configured client to the interface. After the module stops, a new call waits for the next start.

```typescript
import { GetClient } from "@antelopejs/interface-stripe";

async function listCharges() {
  const client = await GetClient();
  const charges = await client.charges.list({ limit: 10 });
  return charges;
}
```

### Returns

`Promise<Stripe>` resolves to the configured Stripe SDK client.

Use `GetClient` for direct access to the Stripe SDK, for the operations that the other interface functions do not cover.

## `InitializePayment`

Creates a Stripe payment intent and stores your identifier in its `metadata.payload` field. The identifier ties the payment intent to an entity in your application, such as an order or an invoice.

```typescript
import { InitializePayment } from "@antelopejs/interface-stripe";

async function createOrderPayment(orderId: string) {
  const paymentIntent = await InitializePayment(orderId, {
    amount: 2500, // $25.00 in cents
    currency: "usd",
    payment_method_types: ["card"],
  });

  return {
    clientSecret: paymentIntent.client_secret,
    paymentIntentId: paymentIntent.id,
  };
}
```

### Parameters

| Parameter | Type                               | Required | Description                                       |
| --------- | ---------------------------------- | -------- | ------------------------------------------------- |
| `id`      | `string`                           | Yes      | Your identifier, stored in `metadata.payload`.    |
| `params`  | `Stripe.PaymentIntentCreateParams` | Yes      | The Stripe parameters that create the intent.     |
| `options` | `Stripe.RequestOptions`            | No       | Stripe request options, such as `idempotencyKey`. |

### Returns

`Promise<Stripe.PaymentIntent>` resolves to the created payment intent.

The other `metadata` keys that you pass in `params` stay as they are. `InitializePayment` sets `metadata.payload` to `id` and replaces any `payload` value that you passed. It writes the `metadata` into the `params` object that you pass, before it sends the request.

## `WaitForPayment`

Waits for a payment intent to reach a terminal state. The promise resolves with the payment intent when its status becomes `succeeded`. It rejects with the cancellation reason when its status becomes `canceled`.

`WaitForPayment` first retrieves the payment intent from Stripe. If the intent is already in a terminal state, the function returns or throws at once and registers no watcher.

```typescript
import { WaitForPayment } from "@antelopejs/interface-stripe";

async function awaitPayment(paymentIntentId: string) {
  try {
    const completedIntent = await WaitForPayment(paymentIntentId);
    console.log("Payment succeeded:", completedIntent.id);
    return completedIntent;
  } catch (reason) {
    console.error("Payment canceled or status retrieval failed:", reason);
    throw reason;
  }
}
```

### Parameters

| Parameter         | Type     | Required | Description                                      |
| ----------------- | -------- | -------- | ------------------------------------------------ |
| `paymentIntentId` | `string` | Yes      | The ID of the Stripe payment intent to wait for. |

### Returns

- `Promise<Stripe.PaymentIntent>` resolves when the intent succeeds.
- The promise rejects with the `cancellation_reason` of the intent when the intent is canceled. The reason is one of the Stripe cancellation reason strings, or `null` when Stripe gives no reason.
- The promise rejects with the Stripe error when the retrieval of the intent fails.

Calls to `WaitForPayment` with the ID of an intent that is still pending share one promise. The interface keeps one waiter per intent, and every caller gets the same result.

## `CompletePayment`

Completes a payment with a charge from a chargeable Stripe Source. The function retrieves the payment intent to read its amount and currency. It then creates the charge with an idempotency key from the `payload` metadata, and stores the ID of the charge in the metadata of the payment intent.

```typescript
import { CompletePayment } from "@antelopejs/interface-stripe";
import type Stripe from "stripe";

async function finalizePayment(paymentIntentId: string, source: Stripe.Source) {
  try {
    await CompletePayment(paymentIntentId, source);
    console.log("Payment completed successfully");
  } catch (error) {
    console.error("Failed to complete payment:", error);
  }
}
```

### Parameters

| Parameter         | Type            | Required | Description                                             |
| ----------------- | --------------- | -------- | ------------------------------------------------------- |
| `paymentIntentId` | `string`        | Yes      | The ID of the Stripe payment intent to complete.        |
| `source`          | `Stripe.Source` | Yes      | A Source object that must have the `chargeable` status. |

### Behavior

1. Checks that the status of the Source is `chargeable`. If it is not, the function throws an `Error` with the message `Source is not in chargeable state`.
2. Retrieves the payment intent to read its `amount` and `currency`.
3. Creates a charge from the Source, with the payment intent ID in the `paymentIntentId` metadata of the charge. The idempotency key is `metadata.payload`, or the payment intent ID when the intent has no `payload`.
4. Stores the ID of the created charge in the `charge` metadata key of the payment intent.

The Source must have the `chargeable` status before you call this function. A Source in any other state makes the function throw before it calls Stripe.
